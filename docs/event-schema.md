# Event and OTLP validation

The public contract is [spec.md sections 3–4](spec.md). `@journeygap/core` exports `parseOtlpJson(text, validatedRelayConfig, receivedAtMs?)`, `sanitizeAttributes(input, allowlist)`, and the relevant types. Validate Relay configuration at startup with `validateRelayConfig()` before parsing events. Parsing returns `events` (step/navigation/error), `journeyEvents` (step rows), and `sanitized` (a reconstructed OTLP envelope). It performs no I/O or upstream delivery. Persist step rows idempotently by eventId; receipt timestamps are separate from client timestamps. Clock-skew exclusion belongs to analysis.

The parser follows [OTLP JSON protobuf encoding](https://opentelemetry.io/docs/specs/otlp/#json-protobuf-encoding): lowerCamelCase envelopes, hexadecimal trace/span IDs, scalar AnyValue fields, and decimal 64-bit timestamps. Integer attribute values accept safe numeric or decimal string representations; unsafe integers are rejected or dropped. Reconstruction emits string intValue/fixed64 values and numeric enum kind. This is a validation/reconstruction utility; browser output will use the official OpenTelemetry exporter, not a custom exporter.

Only configured services and journey/step combinations are accepted for JourneyGap spans. Required schema version, UUIDv4 event/session/instance IDs, event-specific attributes, timestamps, and trace/span IDs are checked. Navigation is a categorical route ID; errors are render/network/unknown, without message or stack. Other spans are discarded, including those from unregistered services. Invalid JourneyGap spans fail the whole request with `OtlpValidationError`, whose message contains no submitted values. Empty envelopes succeed.

Bounds: UTF-8 input at most 256 KiB, array length at most 1000, depth at most 16, at most 20000 traversed nodes. HTTP timeout/content-type/rate/CORS checks belong to Relay. Duplicate attribute keys are rejected. Unknown protobuf message fields are ignored and never copied. Forwarding must use the reconstructed envelope, not the submitted payload: resource attributes are restricted to service name/version/environment; scope is fixed; span events, links, parent IDs, status messages, unknown attributes and other fields are omitted.

Custom `app.` attributes require a service-specific allowlist, up to 10 keys. Boolean and finite safe numeric values are allowed. Categorical strings use a deliberately stricter subset than the schema's maximum: lowercase slugs up to 32 characters, no long opaque runs or obvious sensitive terms. Values with spaces, email syntax, URLs, or long text are dropped. Keys suggesting input, users, credentials, or other sensitive data are dropped even when listed. Application getters are not invoked. Version labels accept up to 64 alphanumeric/version punctuation characters with obvious sensitive terms excluded.

Heuristics cannot prove arbitrary data is nonpersonal. Only pass application-defined low-cardinality categories, never raw input or user IDs. The SDK and receiver both apply the same filter. Fixtures use synthetic IDs and values only.
